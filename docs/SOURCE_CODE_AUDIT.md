## Findings

### P0 follow-up

- Backup manifests and preset packs now stage serialized data in a unique, exclusively created sibling file, flush it and replace the destination with `std::fs::rename`. Errors clean up the staged file when possible. Interruption before rename can leave an orphan temporary file, which is ignored by readers. This is per-file replacement, not a multi-file restore transaction or a guarantee against power loss. The schema and 4 MiB limit remain intact, and reads now enforce the cap on actual bytes.
- Routing, hotkey and diagnostic writers have separate replacement paths. Presets move the old file to a backup before publishing. AI import updates two related files and needs a separate transaction design. These paths were inventoried without changing their semantics.
- Production CSP remains under review. The renderer uses bundled assets, Windows IPC and dynamic meter styles. Validate any candidate in packaged WebView2 with device selection, event delivery, dialogs, record/export and updater controls before enabling it. Capabilities scope plugin permissions to the main window. The updater launch gate is locally tested, while signed upgrade and rejection still require release artifacts and keys. Artifact hashes do not constitute publisher signatures.
- npm audit reported nine moderate dependency findings in the ESLint toolchain rooted in GHSA-g3hv-75wg-m249. It exited successfully at the high threshold. Cargo Audit reported RUSTSEC-2026-0594 (cookie 0.18.2) and RUSTSEC-2026-0592 (url 2.5.8), plus six warnings. These are dependency findings. Application reachability and patched locked builds remain to be validated. No signing material was inspected.
- The Windows dependency tree includes cookie through Tauri runtime and Wry, and url through Tauri tooling and runtime dependents. Treat the advisories as open until compatible targeted updates are verified. The preset repository applies schema and ID validation. The AI manager validates manifest metadata and checks ONNX bytes against the manifest digest, which establishes content agreement but does not authenticate the publisher. Review custom command path authorization independently of plugin dialog permissions.

- High, confirmed code behavior: backup/mod.rs has remove-before-rename writes (lines 69–71 and 177–179). A replacement failure after deletion can lose the previous destination. Similar patterns in routing/mod.rs and ai/manager.rs need individual ownership and interruption review. No user data loss was reproduced.
- High, release gap: the app has a cable sink and reports its own routing state. Endpoint enumeration and sink activity cannot establish received audio in an external application.
- Medium, confirmed configuration: tauri.conf.json sets production CSP to null. Review a restrictive desktop policy against local assets and IPC. capabilities/default.json scopes dialog/updater/restart to main. Review authorization within custom commands separately, including path handling, size bounds, symlinks and ZIP/JSON assumptions where relevant.
- Medium, realtime risk: stream.rs drains pending soundboard commands inside DSP output handling and records timing in the capture callback. Work is bounded by queue capacity at any instant, but concurrent refill and voice count warrant burst profiling. Verify allocations and callback budgets with instrumentation, including downstream DSP dependencies. No callback race, crash or leak was established.
- Maintainability: lib.rs hosts IPC, startup and multiple feature coordinators. App.tsx centralizes feature assembly. Split along existing service boundaries only when tests protect behavior. React device, runtime, routing and recording polling has distinct cadences. Measure concurrent IPC and cleanup before consolidating.
- Dependencies: lock/installed baseline includes React 19.3.1, TypeScript 6.0.3, Vite 8.3.5, Tailwind 4.3.3, Tauri JS CLI/API 2.12.4, Rust Tauri 2.12.5, CPAL 0.18.2, Signalsmith Stretch 0.1.3 and nnnoiseless 0.5.2. Dialog, updater and process have frontend/backend counterparts. Review dependency usage and duplicate versions with `npm ls --all` and `cargo tree -d` before removing anything. No incompatible or unused dependency was established. Advisory and transitive license checks remain open. No project LICENSE was found among tracked files.
- Security review scope: preset IDs and model manifests have negative tests. Hash verification checks integrity relative to the supplied manifest, so publisher trust is a separate question. Signed updater fails closed without configured key. Check file-size enforcement at read time, partial writes and privacy of device names in diagnostics. No exploit or vulnerability identifier was established.
